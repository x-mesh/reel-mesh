# 선정: 무엇을 녹화할지 정하기

이 단계는 녹화 없이 끝난다. 이 단계에서는 `record`, `review`, `render`를 실행하지 않는다. 마지막에 `validate`만 실행한다.

## 1. 저장소에서 읽을 것

1. README의 기능 설명과 시작 방법
2. 기능 목록이 드러나는 파일: 라우트, 메뉴, 명령 목록, 요구사항 문서
3. 최근 커밋과 변경 파일. 새 기능이 시연 후보가 된다.
4. 실행 방법(`Makefile`, `package.json` 스크립트)과 호스트 종류(웹앱, Chrome 확장, 정적 HTML)
5. 이미 있는 시연 이미지와 그 위치

## 2. 사용자에게 묻는 것

저장소에서 알 수 없는 항목만 묻는다. 질문은 한 번으로 끝낸다. 항목마다 기본값을 제시하고, 답이 없으면 기본값으로 진행한다.

| 항목 | 기본값 |
|---|---|
| 보는 사람 | 처음 보는 사용자 |
| 길이 예산 | 30초 안팎 |
| 자막 언어 | README 기본 언어 |
| 크기 예산 | GIF 3MB 이하 |
| 화면 구성 | 페이지만. 확장이면 페이지와 사이드 패널 |

후보를 보여 주기 전에 이 질문을 따로 하지 않는다. 후보 제시와 질문을 한 메시지로 묶고, 그 메시지가 사용자 확인 1(후보 선택)이다.

## 3. 스토리보드 후보 형식

후보는 1~3개다. 각 후보에 아래 항목을 모두 적는다.

```text
### 후보 <A/B/C>: <한 줄 제목>

- 보여 줄 기능과 순서: 1) ... 2) ... 3) ...
- 단계별 자막과 기대 상태:
  | 단계 | 자막 | 기대 상태(selector) |
- 화면 구성과 크기: 예) 페이지 1040x760 + 사이드 패널 360x760, 좌우 배치
- 예상 길이: 예) 약 28초
- 필요한 준비: 서버 명령, 확장 로드 경로, 예제 데이터
- 녹화가 어려운 장면: 예) 실제 에이전트 세션이 필요한 대화. 없으면 "없음"
- 화면 문제: 녹화 전에 발견한 꺾인 글자, 겹치는 요소. 없으면 "없음"
```

후보를 낸 뒤에 후보 중 하나를 추천하고 이유를 한두 문장으로 붙인다.

### 예시 스토리보드

`examples/scenarios/selected-example.yaml`이 아래 후보 B를 선택했을 때 저장하는 시나리오다.

```text
### 후보 B: 제목을 고르고 단추를 눌러 상태 변화 보이기

- 보여 줄 기능과 순서: 1) 앱 열기 2) 제목 선택 3) Click me 더블클릭
- 단계별 자막과 기대 상태:
  | 단계 | 자막 | 기대 상태 |
  | 1 | Open the app | 없음 |
  | 2 | Select the title | h1 |
  | 3 | Double-click the button | 없음 |
- 화면 구성과 크기: 페이지 800x600, 한 화면
- 예상 길이: 약 6초
- 필요한 준비: 개발 서버 http://127.0.0.1:5173/
- 녹화가 어려운 장면: 없음
- 화면 문제: 없음
```

## 4. 선정 기준

- 첫 장면 5초 안에 "무엇을 하는 도구인지"가 보여야 한다.
- 장면마다 화면에 눈에 띄는 변화가 있어야 한다. 변화가 없는 설정 화면은 뺀다.
- 다른 도구와 다른 기능을 앞에 둔다.
- 외부 계정, 결제, 실제 에이전트처럼 재현할 수 없는 장면은 후보에서 빼거나 "녹화가 어려운 장면"에 따로 표시한다.
- 개인 이메일, 비밀값, 다른 탭 제목이 보일 수 있는 장면은 시나리오의 `mask`로 가릴 수 있는지 확인한다.

## 5. 녹화 전 화면 문제 알림

저장소의 CSS와 화면을 읽다가 아래 문제가 보이면 녹화 전에, 후보 메시지 안에서 알린다. 이 문제는 앱의 기존 결함이어서 그대로 녹화하면 GIF에 찍힌다(F11).

- 지정한 화면 크기에서 글자나 버튼이 두 줄로 꺾인다.
- 요소가 서로 겹치거나 화면 밖으로 넘친다.
- 자막이 놓일 위치(기본은 아래쪽)에 중요한 버튼이 있다. 화면별로 `caption.position`을 `top`으로 바꿀 수 있다.

실제 화면은 이 단계에서 열지 않는다. 코드와 스타일에서 읽은 추정이면 "추정"이라고 적고, 확정은 검토 단계에서 한다.

## 6. 선택을 시나리오 파일로 저장

사용자가 후보를 고르면 그 후보를 시나리오 파일로 쓰고 `validate`만 실행한다.

```bash
reel-mesh validate demo/<name>.yaml
```

exit 0이 나오면 선정이 끝난다. 다음은 `SKILL.md`의 사전 점검 단계다. 시나리오 필드는 `scenario-format.md`를 따른다.
