# 검토 체크리스트

`review`가 만든 `.reel/<name>/review/contact-sheet.png`(장면 모음)와 `step-<n>.png`(단계별 마지막 프레임)를 에이전트가 이미지로 직접 열어 확인한다. 파일이 있다는 것만 확인하고 넘어가지 않는다.

## 확인 순서

1. `contact-sheet.png`를 열어 흐름 전체를 본다. 의도한 순서로 화면이 바뀌는지, 같은 장면이 길게 반복되지 않는지 본다.
2. 이상이 보이거나 기능 전환점인 단계의 `step-<n>.png`를 원본 크기로 연다.
3. 아래 항목마다 "해당 없음", "문제 있음(위치)"을 판단한다. 판단하지 못한 항목은 못 했다고 보고한다.

## 항목

| 항목 | 확인 내용 | 문제가 있을 때 |
|---|---|---|
| 열린 채 남은 메뉴 | 다음 단계로 넘어갔는데 드롭다운, 팝오버, 툴팁이 계속 열려 있다 | 닫는 `press`(예: `Escape`)나 빈 곳 `click` 단계를 추가한다 |
| 가려진 버튼 | 자막이 버튼이나 중요한 UI를 가린다(F5) | `caption.position`을 그 화면에서 `top`으로 바꾼다 |
| 이전 상태 복원 | 앞선 녹화의 로그, 선택, 입력값이 처음 화면에 보인다(F6) | 그 저장 키를 `state.localStorage` 또는 `state.chromeStorage`에 추가한다. 페이지를 떠날 때 다시 쓰는 앱이면 `restoreViaBlankOrigin`을 켠다 |
| 꺾인 글자 | 버튼이나 제목이 두 줄로 꺾이거나 잘린다(F11) | 화면 `size`를 키우거나, 앱의 문제로 보고하고 사용자에게 처리 방법을 묻는다 |
| 다른 탭 제목, 개인정보 | 패널의 탭 선택 목록, 이메일, 토큰, 사용자 이름 등이 찍혀 있다(RM-12) | `mask`에 selector를 추가하거나 `extension.pinTo`로 대상 탭을 고정한다 |
| mask 누락 | 가려야 할 요소가 가려지지 않았다. 또는 `record` 출력에 `WARN mask '...'가 녹화 동안 한 번도 일치하지 않았습니다`가 있다 | selector를 고친다. 경고가 있으면 그 selector는 어느 화면에서도 일치하지 않은 것이다 |
| 기대 상태 | 마지막 프레임이 자막이 설명하는 상태와 다르다 | 단계에 `expect`와 `retry`를 추가한다 |
| 화면 간 정합 | 여러 화면이 같은 시점을 보여 주는지, 경계선이 보이는지 | `layout`과 `size`를 확인한다 |

## 보고

- 문제가 없으면 확인한 이미지 이름과 "문제 없음"을 한 줄로 보고하고 변환으로 넘어간다.
- 문제가 있으면 항목, 이미지 이름, 고칠 시나리오 부분을 보고하고 시나리오를 고친다. 고친 뒤에는 파일에서 변경이 반영됐는지 읽어 확인하고, `validate` 후 다시 녹화한다(F3).

## 한계

`audit`은 이미지 속 글자를 검사하지 않는다. 화면에 찍힌 비밀값과 개인정보는 이 체크리스트의 이미지 확인으로만 찾을 수 있다.
